    REST API reference¶

    Auto-generated from the backend's code-derived OpenAPI spec (utoipa annotations on each handler). Run scripts/docs/regen.py to refresh — CI does this on every push. The same spec is served at GET /api/v1/openapi.json from a running backend, or exported offline with appcontrol-backend --export-openapi <path>. Load either into Postman, Insomnia, Redoc, or Swagger UI for an interactive view.

    API version: 0.1.0

    Base URL: /api/v1 (relative to the backend host)

    Enterprise platform for operational mastery and IT system resilience. Maps applications as dependency graphs (DAGs), monitors component health, orchestrates sequenced start/stop/restart operations, and manages DR site failover.

    This document is generated from the handler source — never hand-edited.

    Authentication¶

    Every endpoint (except /health and /ready) requires authentication. Two schemes are supported:

    • JWT bearer — for browser sessions. Obtained from /api/v1/auth/login (local), the OIDC callback, or the SAML assertion consumer. Pass it as Authorization: Bearer <jwt>.
    • API key — for schedulers, CI, and the appctl CLI. Created in the UI under Settings → API Keys. Pass it as Authorization: Bearer <key> (same header; the backend tries both schemes).

    All API key activity is recorded in action_log with actor_type='api_key'.

    GET /apps/{app_id}/site-overrides¶

    GET /api/v1/apps/:app_id/site-bindings

    Returns all site bindings for components in the given application. This is based on binding profiles (which define where components run) merged with any command overrides from site_overrides table.

    Each component shows: - All sites where it has a binding (from binding_profile_mappings) - The agent assigned for each site - Any command overrides for that site (from site_overrides) - Whether this is the active profile

    Parameters

    • app_id (path, string, required) — Application id

    Responses

    • 200 — Per-site command/agent overrides for this application
    • 403 — Forbidden
    • 404 — Not found

    POST /apps/{id}/cancel¶

    Request cancellation of a running operation on an application. The operation will check for cancellation and stop gracefully.

    Parameters

    • id (path, string, required) — Application id

    Responses

    • 200 — Cancellation requested. Body indicates whether an active operation was found
    • 403 — Forbidden

    POST /apps/{id}/force-unlock¶

    Force-release an operation lock. Use as last resort when cancel doesn't work. This immediately removes the lock, potentially leaving the operation orphaned.

    Parameters

    • id (path, string, required) — Application id

    Responses

    • 200 — Lock force-released or no lock found
    • 403 — Forbidden (requires Manage permission)

    PUT /apps/{id}/resume¶

    PUT /api/v1/applications/:id/resume

    Resume a suspended application. The agent will restart health checks for all components in this application.

    Parameters

    • id (path, string, required) — Application id

    Responses

    • 200 — Application resumed
    • 403 — Forbidden (requires Manage permission)
    • 409 — Not suspended

    PUT /apps/{id}/suspend¶

    PUT /api/v1/applications/:id/suspend

    Suspend an application. The agent will stop health checks for all components in this application until it is resumed.

    Parameters

    • id (path, string, required) — Application id

    Responses

    • 200 — Application suspended
    • 403 — Forbidden (requires Manage permission)
    • 409 — Already suspended
