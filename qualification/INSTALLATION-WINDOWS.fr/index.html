    Installer AppControl sur OpenShift depuis Windows¶

    Le parcours à utiliser pour la première installation chez le client : un ZIP, un assistant PowerShell, puis une vérification dans le navigateur.

    Le poste Windows sert à piloter l’installation. AppControl s’exécute dans le projet OpenShift dédié : quatre pods et un disque persistant de 2 Gio. L’assistant utilise PowerShell Windows et .NET Framework, avec les outils OpenShift, Helm et de transfert d’images fournis dans le ZIP. Python n’est ni installé ni nécessaire sur le poste client. Aucun Docker Desktop, WSL ou poste Linux n’est nécessaire.

    Poste attendu : Windows 64 bits avec Windows PowerShell 5.1 et .NET Framework 4.8, selon la configuration approuvée par l’équipe poste de travail.

    1. Préparer le créneau et récupérer le ZIP¶

    Obtenir ces informations auprès de l’équipe OpenShift avant le jour de la démo :

    À préparer Exemple ou précision
    Projet dédié déjà créé appcontrol-evaluation, avec les droits de déploiement dans ce projet.
    Connexion OpenShift Adresse du serveur et jeton de connexion, ou kubeconfig déjà utilisable sur le poste.
    Registre pour les images Registre intégré OpenShift accessible depuis le poste, ou endpoint Docker Artifactory approuvé avec droits d’import.
    Lecture des images par les pods Automatique pour le registre intégré dans le même projet ; secret de pull à prévoir pour un registre privé externe.
    Stockage Classe de stockage par défaut utilisable, ou nom de celle à employer ; 2 Gio disponibles.
    Accès à l’application Deux Routes sur le domaine du cluster : HTTPS pour l’interface, WSS pour la gateway. Le poste doit faire confiance à leurs certificats.

    Prévoir des nœuds Linux AMD64 et des quotas compatibles : les quatre services réservent au total 1,1 vCPU et 960 Mio ; la démonstration ajoute un petit agent de 0,05 vCPU et 32 Mio. Les limites maximales des conteneurs sont plus élevées : l’équipe plateforme doit également les accepter.

    Télécharger les deux fichiers depuis la release AppControl 1.20.4 :

    • Kit Windows complet — ZIP
    • Empreinte SHA-256

    Le ZIP contient les cinq images du produit et les outils Windows nécessaires. Il peut être transféré sur le poste client par le canal approuvé ; l’installation n’exige ensuite aucun téléchargement sur Internet. Le poste doit pouvoir joindre l’API OpenShift, le registre et les Routes de l’application.

    Depuis PowerShell, dans le dossier contenant les deux fichiers, vérifier le ZIP :

    $archive = 'appcontrol-openshift-windows-1.20.4-1.zip'
$attendu = ((Get-Content "$archive.sha256" -Raw).Trim() -split '\s+')[0]
$obtenu = (Get-FileHash $archive -Algorithm SHA256).Hash
if ($obtenu -ne $attendu) { throw 'Empreinte incorrecte : ne pas utiliser cette archive.' }
'Empreinte conforme'

    Puis utiliser Extraire tout dans l’Explorateur Windows, dans un dossier court et local dans votre profil utilisateur, par exemple Documents\AppControl\kit. Ne pas lancer l’assistant directement depuis la vue du ZIP.

    2. Ouvrir l’assistant¶

    Dans l’Explorateur, ouvrir le dossier extrait qui contient Installer-AppControl.ps1. Cliquer dans la barre d’adresse, taper powershell, puis appuyer sur Entrée. La fenêtre Windows PowerShell s’ouvre directement au bon endroit. Lancer :

    .\Installer-AppControl.ps1

    Il n’est pas nécessaire de lancer PowerShell en administrateur. Si la politique de la banque bloque le script ou un exécutable fourni, demander sa validation à l’équipe poste de travail ; ne pas modifier la politique d’exécution du poste. Les scripts utilisent le mode PowerShell FullLanguage standard ; ils ne contournent ni les règles d’exécution ni les restrictions de la banque.

    L’assistant accompagne les étapes suivantes :

    1. Connexion et projet. Choisir la connexion existante ou saisir l’adresse du serveur et un jeton masqué, puis le projet dédié.
    2. Registre. Choisir le registre intégré OpenShift ou Artifactory. Dans ce dernier cas, utiliser l’adresse Docker fournie par l’équipe plateforme, pas l’adresse de l’interface web Artifactory. Les droits d’import du poste et les droits de lecture des pods sont deux accès distincts.
    3. Préparation. Vérifier les droits, le stockage et les noms des Routes, puis importer les images en conservant leurs empreintes. Les images sont déjà compilées : aucune construction n’a lieu chez le client.
    4. Installation. Confirmer la cible affichée ; l’assistant déploie AppControl et vérifie sa gateway.
    5. Recette proposée. Sur ce projet d’évaluation, exécuter la démonstration synthétique pour vérifier le fonctionnement complet.

    L’assistant conserve la configuration et les secrets dans un dossier privé sous %LOCALAPPDATA%\AppControl\Installations, avec des permissions Windows limitées. Il indique le chemin exact à conserver pour reprendre la même installation. Ne pas copier ce dossier dans Git, dans un rapport ou dans le ZIP partagé.

    Pour reprendre après une interruption, copier la commande Reprendre affichée par l’assistant : elle sélectionne son fichier assistant.json privé. Conserver ce dossier permet de réutiliser les identifiants, les certificats et les images déjà importées. Si le jeton OpenShift a expiré, l’assistant demandera une nouvelle connexion. Une reprise peut redémarrer la gateway de cette installation ; la réaliser pendant le créneau d’évaluation.

    3. Ouvrir AppControl et constater le résultat¶

    À la fin, l’assistant indique l’URL de l’interface et l’emplacement privé des identifiants administrateur. Ouvrir cette URL dans le navigateur et se connecter.

    Si la recette a été exécutée, ouvrir l’application Qualification dependencies… identifiée dans son rapport :

    • Start All : database-probe démarre avant api-probe ; les deux passent au vert.
    • Stop All : les composants s’arrêtent dans l’ordre inverse.
    • Ouvrir l’historique pour constater les commandes et leur résultat.

    La recette complète vérifie aussi les refus de permission, l’enrôlement de l’agent, les reconnexions et la persistance. Elle redémarre la gateway, le backend et PostgreSQL : l’exécuter uniquement sur cette installation d’évaluation isolée. Les commandes de démonstration utilisent des marqueurs de test ; aucun service métier de la banque n’est appelé.

    Conserver le rapport de recette et le dossier privé d’installation séparément. Une installation réussie laisse AppControl disponible : il n’est pas nécessaire de garder PowerShell ouvert pour utiliser l’application.

    Si une étape bloque¶

    Message ou symptôme Prochaine action
    Connexion refusée ou jeton expiré Renouveler la connexion OpenShift avec la procédure de la banque, puis reprendre le même dossier d’installation.
    Droit manquant dans le projet Faire attribuer le droit indiqué par le précontrôle ; les pods n’ont pas besoin de cluster-admin ni de SCC anyuid.
    Registre intégré inaccessible depuis Windows Demander sa Route approuvée ou utiliser le registre Artifactory de la banque.
    Image non récupérable par un pod Vérifier l’adresse de registre, le secret de pull et la confiance TLS des nœuds.
    Volume en attente Vérifier la classe de stockage et le quota du projet.
    Erreur de certificat Faire installer la CA approuvée dans les magasins de confiance concernés ; ne pas désactiver TLS.
    Dossier d’état manquant pour une installation existante Restaurer le dossier privé d’origine avant de poursuivre, afin de conserver les identifiants et certificats.

    Le projet dédié sépare les objets et les données de cette installation. Il n’alloue pas à lui seul des nœuds physiques réservés ; l’isolation réseau et les quotas restent ceux définis par la plateforme OpenShift du client.

    Après la première démonstration¶

    La gateway est déjà incluse. Pour raccorder un agent extérieur au cluster, prévoir sa connexion sortante WSS 443 vers la gateway, son certificat de confiance et un jeton d’enrôlement à usage unique. Suivre ensuite la procédure d’enrôlement.

    Ce parcours fournit une évaluation mono-instance. Le raccordement au SSO, à la PKI et à la base gérée du client, la sauvegarde/restauration et la haute disponibilité se cadrent ensuite pour le POC. Les certificats de service générés durent 90 jours et le jeton de gateway 30 jours ; leur renouvellement est explicite.

    Les rapports CVE de la release 1.20.4 concernent les images du produit. Les exécutables Windows ajoutés sont les distributions officielles d’OpenShift, Helm et regctl, avec versions et empreintes fixées dans tools.lock.json ; ce fichier n’est pas un rapport de scan de ces exécutables. Ils peuvent être soumis au contrôle du poste de travail avant le créneau.

    Les preuves de qualification du kit Windows doivent être lues avec le paquet distribué : elles précisent la version de Windows et de PowerShell réellement testée. Elles complètent les preuves des images AppControl 1.20.4 sans modifier le kit Linux/macOS original. Le rapport exécuté dans le projet du client reste la preuve de son installation propre.
