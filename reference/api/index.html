    REST API reference¶

    Auto-generated from the backend's code-derived OpenAPI spec (utoipa annotations on each handler). Run scripts/docs/regen.py to refresh — CI does this on every push. Open /api-docs on your AppControl instance for the bundled Swagger UI and see the guided walkthrough (FR). The same spec is served at GET /api/v1/openapi.json, or exported offline with appcontrol-backend --export-openapi <path>.

    API version: 1.24.1

    Base URL: /api/v1 (relative to the backend host)

    Enterprise platform for operational mastery and IT system resilience. Maps applications as dependency graphs (DAGs), monitors component health, orchestrates sequenced start/stop/restart operations, and manages DR site failover.

    This document is generated from the handler source — never hand-edited. Coverage is incremental: absence from this document does not mean an endpoint is unavailable. The external-AI map generation, validation and import workflow is documented here. In same-origin Swagger UI, the current AppControl login is used automatically. For another identity, authorize with either an AppControl JWT or ApiKey <key>; import permissions are separate from validation access.

    Authentication¶

    Protected operations use the following alternatives. Authentication does not override application/site permissions or the limits of a restricted API key.

    • apiKeyAuth — Enter ApiKey <key> for a personal or service API key. The Authorization header (not X-API-Key) is accepted by the authentication middleware.
    • bearerAuth — AppControl session JWT. Pass as Authorization: Bearer <token>. An identity-provider token is not accepted directly as an AppControl session.
    • embeddedSessionAuth — Short-lived simulation-only bearer issued by /apps/{id}/embedded-sessions. Not accepted by Operations APIs. Never put this token in URLs or browser storage.
    • sessionCookie — Existing AppControl browser session (HttpOnly cookie, sent automatically for same-origin requests). Sign in through AppControl; do not paste the cookie into Swagger UI.

    All API key activity is recorded in action_log with actor_type='api_key'.

    Endpoint detail¶

    Tag — Agents¶

    GET /agents¶

    Lists enrolled agents in the caller organization. The response object contains agents[]. Use agents[].id for import profile mappings and agents[].gateway_id to choose the gateway scope. connected is live connection status; is_active is administrative status. An arbitrary hostname does not enroll an agent.

    Responses

    • 200 — Object with agents array; includes id, hostname, gateway_id, gateway_name, connected, is_active, OS/version and heartbeat metadata
    • 401 — Authentication required
    • 403 — Insufficient API scope

    GET /apps/{app_id}/site-overrides¶

    GET /api/v1/apps/:app_id/site-bindings

    Returns all site bindings for components in the given application. This is based on binding profiles (which define where components run) merged with any command overrides from site_overrides table.

    Each component shows: - All sites where it has a binding (from binding_profile_mappings) - The agent assigned for each site - Any command overrides for that site (from site_overrides) - Whether this is the active profile

    Parameters

    • app_id (path, string, required) — Application id

    Responses

    • 200 — Per-site command/agent overrides for this application
    • 403 — Forbidden
    • 404 — Not found

    GET /map-generation/contract¶

    Parameters

    • profile (query, any, optional) — standard (default), mock-linux, mock-windows
    • include_catalog (query, boolean, optional) — Include the caller organization's catalog; requires global read/design for scoped API keys
    • catalog_types (query, string, optional) — Optional comma-separated catalog type keys; requires include_catalog=true. Maximum 100 entries and 256 KiB of catalog data.
    • If-None-Match (header, ['string', 'null'], optional) — ETag from a prior identical request, including quotes. A matching digest returns 304 without a body.

    Responses

    • 200 — Versioned prompt, JSON Schema, examples and selected profile. Does not call an AI or change applications.
    • 304 — If-None-Match matches; empty body, reuse the cached contract
    • 400 — Invalid profile or catalog selection
    • 401 — Authentication required
    • 403 — Insufficient catalog access

    Tag — Map imports¶

    POST /import/execute¶

    POST /api/v1/import/execute

    Publishes a reviewed map with explicit component-to-agent UUID mappings supplied outside content. Strict generated maps must not also contain binding_profiles; use /import/json for that alternative. conflict_action defaults to fail; update replaces the imported configuration of the application with the same name after authorization and binding checks. Periodic checks may begin immediately on bound agents. Not a global transaction: after a timeout/server error inspect the application before retrying. Sample UUIDs must be replaced with your enrolled resources.

    Request body

    Content-Type: application/json

    {
  "$ref": "#/components/schemas/ImportExecuteRequest"
}

    Responses

    • 201 — Application created or updated, including active binding profile
    • 400 — Invalid map, profile, agent/site binding, or unsupported embedded profiles
    • 401 — Authentication required
    • 403 — Insufficient scope, application permission or target-site access
    • 409 — Application-name conflict or incompatible generation contract
    • 422 — Malformed request envelope

    POST /import/json¶

    POST /api/v1/import/json Import a v4 native JSON map into the database.

    Creates a new application; not an idempotent upsert. Agent bindings are resolved from hosts/binding_profiles inside the map. generation_contract_version enables strict validation before writes. Review commands first: periodic checks may execute as soon as configuration reaches a bound agent. Import does not itself start or stop the application. After a timeout or server error, inspect the application list before retrying; the import is not a global transaction.

    Request body

    Content-Type: application/json

    {
  "$ref": "#/components/schemas/JsonImportRequest"
}

    Responses

    • 201 — Application created; retain application_id and review warnings
    • 400 — Invalid map, unresolved/ambiguous explicit target, unsupported merge_into_app_id, or invalid site
    • 401 — Authentication required
    • 403 — Insufficient import scope or target-site access
    • 409 — Incompatible generation contract version
    • 422 — Malformed request envelope

    Application errors use the following body shape. Malformed requests rejected by the HTTP framework, authentication middleware, or a reverse proxy may use a different response format:
