    Changelog¶

    All notable changes to AppControl will be documented in this file.

    The format is based on Keep a Changelog, and this project adheres to Semantic Versioning.

    [Unreleased]¶

    [1.27.0]¶

    • Prepare Markdown procedures, documentation and missing map commands with selected skills and Knowledge sources. Keep command proposals separate from maps until independently approved and explicitly applied. Reuse reviewed Markdown documentation in Map Builder. Record the site of Discovery observations and require exact site provenance for site-specific proposals.
    • Unify packaged assistant guides, discovery skills and versioned application procedures in the CapabilityCatalog. Filter by purpose, application and component type, inspect inputs, outputs and real versions, and retain context when opening the existing workspaces.

    • Keep historical skill links and the downloadable skills feed; preserve application/site permissions and independent approval when navigating from the catalog. Add the application procedure guide for external assistants.

    • Add application recovery dossiers with source knowledge, pinned architecture snapshots, multiple versioned procedures, independent review, explicit reference adoption and immutable scoped evidence. Retain earlier references and drafts after failed AI refinement, conflicting saves and failed execution. Preserve the refinement request while the operator reviews and selects another revision.

    • Refine procedures through the existing client AI connector with explicit source selection. Export a version-bound SKILL.md and JSON result contract; keep imported host identity unverified and consolidate reviewed evidence into Knowledge without replacing validated alternatives.
    • Execute approved configured check/start/stop operations through existing AppControl agents with full-plan preflight, current permission and site checks, application leases, positive health verification and command provenance stored before dispatch. Publish terminal results and evidence atomically; preserve failures and interrupted execution history. Keep manual steps, reconstruction and clustered operation paths explicit.
    • Ship additive PostgreSQL and SQLite migrations V085 and V086, together with the guides for application procedures and the Knowledge loop. Restore a compatible backup before reverting to a backend that predates the new Knowledge origins or Discovery site provenance. Existing maps, connector settings and agent enrollment carry over.

    • Explain when a site cannot be deleted because it is still referenced. Administrators can disable the site while keeping its recovery history.

    • Open the recovery dossier to operators with an application grant and access to its recorded recovery site. Show the exact execution site and revision, report drift in the effective configuration, and audit blocked launch attempts.

    • Keep historical recovery evidence accessible by revision, including inactive sites. Preserve procedure and command proposal history when refusing application deletion. Require a documented human review for reference adoption and bind legacy procedure commands to the reviewed gateway and site.
    • Export an approved recovery dossier in an encrypted, versioned format with an offline reader for reviewing its contents and checking its manifest.

    • Add an opt-in controlled full switchover. Require an independently reviewed restoration and reconciliation receipt before advancing from synchronization, and a witness transaction and traffic observation before committing.

    • Verify SAML XML signatures against configured IdP certificates, enforce issuer/audience/time/correlation and durable replay protection, and bind both SAML and OIDC sign-ins to their initiating browser. OIDC validates signed ID tokens, nonce, PKCE and userinfo subject against trusted discovery/JWKS.

    • Bind external identities by issuer and subject, require explicit administrative linking for existing accounts, and reconcile SAML-managed role/team changes without removing locally managed grants. Reject cross-organization workspace, identity, terminal and log operations; make share-link redemption and access mutations atomic with their audit records.
    • Add explicit hybrid, SSO-only and local-only authentication policies, optional named emergency administrators, account-wide session revocation, password-reset invalidation across HTTP/WebSocket/X4B sessions, and consistent new-password limits. Preserve historical login behavior for legacy AUTH_MODE aliases; document required SAML trust settings and V084 migration.
    • Create local users from either PowerShell installer with secure password input or a caller-provided SecureString, without a shared default password. Validate the same password limits as the backend before submitting the account.

    • Clarify the identities and access interface, role provenance, session revocation and expired API keys. Display IdP-managed MFA policy without asserting that a configured SSO connection proves MFA.

    • Prepare Discovery missions from application, catalog or server context using free Markdown skills and reusable agent configurations. Preserve skill versions and plan history, review exact collector operations, and record human approval bound to the immutable canonical plan. Use a dedicated optional Ed25519 key for signed approvals.

    • Download bounded Linux/Python manual collectors and import checked results with mission, skill, target and run provenance. Require explicit review to consolidate observations into existing Knowledge revisions, retain contradictory evidence, and keep manual host identity unverified. Execute an approved typed plan explicitly through existing, opted-in Linux AppControl agents with dedicated signatures, local roots and budgets, verified gateway identity, replay protection and bounded native collectors. Keep manual collection available.
    • Distinguish cancellation requests from authenticated stop confirmations, retain late evidence after disconnection, and never replay a dispatch automatically when its outcome is unknown.
    • Scope legacy discovery reports, correlation and individual scan requests to the current organization.
    • Track sourced support lifecycle facts by component type and software version. Preview and atomically apply a versioned JSON feed, retain separate authorities and configuration history, and display application usage with version uncertainty and permission filtering.
    • Analyze a synchronized document on demand through its existing AI connector to propose lifecycle facts for review. Preserve previous proposals after a failed analysis and keep accepted facts separate from operational map drafts and commands. Ship the protocol schema, examples and catalog administration skill.
    • Configure several named document sources in Knowledge, with separate connection tests, synchronization state, activation and document catalogs. Filter Map Builder by source and keep identical application keys isolated through generation, document reading, refinement and publication. Preserve the existing deployment-managed connector and its source references; the external connector contract remains compatible.
    • Migrate existing saved connector settings without changing the source identity, exact URL, encrypted credential or connection revision. Extend Windows/OpenShift upgrade checks to preserve every configured source.
    • Browse component types as searchable, categorized cards with pagination and a detailed side panel. Keep catalog editing separate from consultation and preserve entered values on a failed save.
    • Browse synchronized source documents directly in Knowledge, independently of map generation. Read and verify an exact JSON revision on demand through the existing connector contract, with administrator access and account-scoped caching.
    • Preserve UTF-8 command output at the truncation boundary and enforce command timeouts after stdout and stderr close; reap timed-out child processes.
    • Keep a component stopping until a health check actually confirms the stop. A failed or timed-out probe no longer authorizes stopping its prerequisites.
    • Persist agent evidence before sending it. Retain command results until the backend confirms database persistence, replay unacknowledged results after reconnect, and bound live-output queues and serialized outbox storage. Require durable dispatch records before sending commands, including agent-level discovery file reads.
    • Replay gateway backlogs progressively without dropping entries above the live channel capacity. Preserve pending writes across connection failures and ignore stale disconnect notifications for replaced agent routes.
    • Share the gateway TLS listener and shutdown path between foreground execution and the native Windows service. Diagnose restrictive Windows Job Objects without weakening detached-process isolation.

    [1.23.1]¶

    The v1.23.0 candidate remained unpublished after the Azure gateway image scan reported CVE-2026-84243. This release updates that image, verifies image scans with comprehensive detection and rejects missing inventories and suppressed findings. All severities and vulnerabilities without a fix are included.

    AppControl Embedded¶

    • Embed a live AppControl map in an approved documentation site with a Web Component. Each simulation uses a private copy of the map and dedicated execution agents. AppControl controls session scope, origin, expiry and audit history.
    • Explore the impact of a failure and simulate application recovery using the AppControl runtime. The main application distinguishes ordinary restart, application reconstruction and infrastructure reconstruction.

    Map generation and catalogue¶

    • Add an X4B workspace that reads application keys and document hashes from a configured source, queues map generation through the customer's AI and validates each candidate. Operators can publish a first map or review the topology changes proposed for an existing map.
    • Preview and update technical catalogue entries in bulk. Catalogue commands prefill new components and can be adjusted per map. The generation contract can include a selection of catalogue entries.

    OpenShift and certificate maintenance¶

    • Deploy a named instance with its sites, hosting, gateways, agents, teams, users and catalogue from one PowerShell configuration. Configure approved Embedded origins and dedicated simulation sites in the same file.
    • Show certificate and token expiry by component. The Windows connector processes approved renewals for installer-managed credentials and records their results. Certificate authorities, platform-managed HTTPS and external agents follow their own renewal procedures.
    • Keep the banking demonstration available from the lightweight kit. The installer can upgrade an existing instance with its original deployment name and private state.

    [1.21.1] - 2026-11-03¶

    The immutable 1.21.0 tag remained unpublished after the release dependency gate identified CVE-2026-118764 in development tooling. This delivery updates the ESLint toolchain and pins its compatible glob consumers to minimatch 11.0.1, without weakening the all-severity production/development release scan. It also updates benchmark fixtures for organization-scoped permission evaluation; runtime permission rules are unchanged. The release includes all features below.

    AI-assisted map generation and publication¶

    • Provide a versioned generation contract with the map ontology, JSON Schema, catalogue selection, examples, Linux/Windows mock command templates and ETag caching. The customer's AI generates the JSON; AppControl makes no model call.
    • Add scoped publication context, prepare and import APIs with explicit placements by site, enrolled host or agent ID, and team grants. A single active application can span several sites. Existing map commands are preserved by default.
    • Treat simulated commands as a generation-prompt choice: the resulting maps use ordinary agents and the ordinary import workflow alongside real applications. Server-side mock materialization remains an explicit optional helper.
    • Add Swagger UI/OpenAPI documentation, PowerShell integration examples and a replayable multi-site demonstration with file-based start/check/stop commands.

    Teams and access control¶

    • Manage application assignments and permissions from Teams in the UI.
    • Enforce organization, site, workspace, expiry and permission-ceiling checks; permission revocations take effect without requiring a new user session.
    • Validate destination bindings before profile activation and switchover, and prevent an import update from silently granting its editor Owner access.
    • Preserve organization-scoped 404 responses and reject expired share links.

    Windows and OpenShift delivery¶

    • Include publication helpers and optional post-install site/agent provisioning in the lightweight PowerShell/oc kit, without bundled images or executables.
    • Retain targeted uninstall, explicit upgrades, Artifactory image rewriting and integrated/external PostgreSQL choices. External PostgreSQL still requires a pre-created dedicated database and an application account with schema rights; the installer does not accept a separate database administrator account.
    • Require an explicit image lock when assembling a new product version so the lightweight kit cannot silently reuse historical images.
    • Preserve demo scenarios in both source and corporate release assets. Release scans and runtime qualification refer to the actual delivered image digests.

    Scope¶

    • Map publication is create-only; it is not an automatic update or an idempotent batch transaction. Review generated commands before import, because periodic checks may run as soon as components are bound to agents.
    • The OpenShift evaluation remains a single-instance deployment with evaluation PKI. Synthetic command tests do not qualify a customer's production procedures.

    [1.20.4] - 2026-10-28¶

    The 1.20.0 tag did not produce a release because GitHub rejected workflow permissions before any build. The 1.20.1 release gates then caught two cold-start installation defects. The 1.20.2 attempt was stopped after inspection of raw RustSec results identified eight advisories despite a successful job status. The 1.20.3 attempt was stopped to correct image references in the generated public documentation and deployment scripts. These tags remain immutable and unpublished; 1.20.4 includes the dependency updates, reliable failure propagation, validated public-registry substitutions and all changes below.

    Security validation corrections¶

    • Update h2 to 0.4.16, quinn-proto to 0.11.18, rustls-webpki to 0.103.16 and webpki-roots to 1.0.10 to resolve the eight RustSec vulnerability advisories.
    • Resolve unsoundness advisories with anyhow 1.0.103, event-listener 5.4.2 and tokio 1.53.3; retain any remaining informational warnings in the audit report.
    • Propagate RustSec and test failures through log pipelines, verify the audit JSON explicitly, and retain audit reports even when the job fails.

    Installation regression fixes¶

    • Align the non-root PostgreSQL image user with its Alpine runtime so new Docker data volumes initialize correctly; keep the existing data directory layout.
    • Fix optional-body argument handling in the demo bootstrap HTTP helper so fetching the enrollment CA sends exactly one authenticated request.
    • Start only the intended Compose test services, handle the packaged agent entrypoint correctly, and retain initialization logs on test failures.

    Release and installation¶

    • Rewrite container registry ownership before repository branding, and reject invalid generated image names in the public documentation and scripts.
    • Integrate the banking reconstruction, AI/MCP incident and Knowledge/GitOps work, including demonstrations and operational guides, into the main release line.
    • Provide a versioned OpenShift client kit with immutable OCI images, Linux binaries, migrations, Helm chart, installer, test recipe, SBOM and provenance.
    • Gate publication on source tests, image and full dependency scans, Windows, Compose and real OpenShift qualification of the exact release artifacts.
    • Include PostgreSQL in image publication and MCP in native release archives.
    • Align Cargo, frontend and Helm versions. Keep prereleases out of stable/latest.

    Safety fixes and limits¶

    • Application deletion is transactional; operation locks and retained Knowledge or reconstruction history return a conflict without partially deleting configuration.
    • Refresh vulnerable runtime bases and dependencies. Azure startup requires verified TLS enrollment and does not log enrollment tokens or fall back to an unauthenticated configuration.
    • Document maintenance interruptions and database recovery explicitly. The initial OpenShift profile is single-backend; it does not certify high availability, customer integrations or recovery of destructive operations.

    OpenShift evaluation upgrade note¶

    • Backend HTTPS egress is now disabled by default. Before upgrading an existing OIDC/SAML/AI-enabled installation, configure networkPolicy.backendHttpsCIDRs for its approved destinations, or explicitly retain the former broad behavior with networkPolicy.allowAnyBackendHttps=true. Otherwise external authentication or AI calls can fail. The isolated password-login evaluation requires neither.

    • The client installer accepts a non-secret JSON configuration, verifies the live gateway connection and exports a public agent CA. External agent enrollment and immutable/offline image transfer procedures are included.

    • Retain two old Deployment revisions by default (global.revisionHistoryLimit), preventing repeated evaluation rollouts from accumulating the Kubernetes default of ten ReplicaSets per service.

    Dependency security¶

    • Update JWT, TLS, randomness and frontend tooling dependencies; validate optional JWT not-before claims, including malformed values.
    • Scan complete workspace manifests in CI in addition to image OS packages and RustSec; retain development findings and reject production vulnerabilities.

    Connection recovery¶

    • Late cleanup of an old gateway socket cannot remove its replacement connection or agent routes. Both socket tasks are stopped before cleanup.

    Added¶

    • Phase 7: Production readiness improvements
    • Migration auto-run: Backend automatically runs sqlx migrations on startup
    • Graceful shutdown: SIGTERM/SIGINT handler with in-flight request draining
    • Configurable CORS: CORS_ORIGINS env var replaces CorsLayer::permissive(); restrictive by default in production
    • Structured JSON logging: LOG_FORMAT=json enables structured JSON logs for log aggregation (ELK, Loki, Datadog)
    • Prometheus metrics: /metrics endpoint with http_requests_total, http_request_duration_seconds, ws_connections_active, agents_connected, state_transitions_total, commands_executed_total, db_pool_connections
    • mTLS fingerprint forwarding: Gateway extracts and forwards agent certificate fingerprints to backend for identity binding
    • Auto-partition maintenance: Background task creates check_events partitions for current + next year; daily maintenance loop
    • React ErrorBoundary: Catches rendering errors in frontend subtrees with retry button
    • Frontend test infrastructure: Vitest + React Testing Library with unit tests for stores, hooks, and components
    • .env.example: Complete reference for all environment variables
    • CHANGELOG.md: This file
    • Phase 8: Production hardening
    • mTLS proxy fingerprint extraction: Gateway extracts X-Client-Cert-Fingerprint header from TLS-terminating proxies (nginx/envoy), overriding agent-reported fingerprint for tamper resistance
    • Security headers middleware: X-Frame-Options DENY, Content-Security-Policy (default-src 'self', frame-ancestors 'none'), HSTS (31536000s + includeSubDomains), X-Content-Type-Options nosniff, X-XSS-Protection, Referrer-Policy, Permissions-Policy
    • JWT HttpOnly cookie support: Multi-source auth (HttpOnly cookie > Bearer header > API key), SameSite=Strict, Secure in production; OIDC and SAML callbacks set cookies directly
    • Token revocation via PostgreSQL: Token fingerprint blacklist checked on every request
    • Kubernetes NetworkPolicies: Backend ingress from frontend+gateway only, frontend ingress from ingress controller, gateway ingress from any (external agents); egress restricted per component
    • Bounded channels with backpressure: Gateway uses mpsc::Sender (1024 agent, 4096 backend) with try_send() — drops messages on full channels to prevent OOM
    • Retransmission with deduplication: DeduplicationTracker with per-agent sequence ID tracking, high watermark advancement, gap detection, ring buffer of 1000 IDs per agent
    • Process kill on timeout: SIGTERM to process group, 5s grace period, then SIGKILL; returns exit_code -1 on timeout
    • Trivy vulnerability scanning in CI: CRITICAL+HIGH severity scan on all 4 Docker images, SBOM generation (CycloneDX format)
    • Structured error handling: ApiError enum (Database, NotFound, Forbidden, Unauthorized, Conflict, Validation, Internal, ServiceUnavailable) with PostgreSQL unique violation → 409, structured JSON error bodies, input validation helpers
    • Configurable database pool: DB_POOL_SIZE (default 20), DB_IDLE_TIMEOUT_SECS (default 600), DB_CONNECT_TIMEOUT_SECS (default 30), max_lifetime 30min, pool metrics reported to Prometheus every 10s
